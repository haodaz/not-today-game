# backend — design (Supabase)

Nothing here is deployed by Kiro. The author and Claude apply the migration, set the secrets and
deploy the function.

## Layout

```
supabase/config.toml
supabase/migrations/0001_init.sql          profiles, runs, kuro_memory, judgement, RLS
supabase/functions/_shared/kuro/*.ts       pure: turns, prompt, judgement schema/validation, LLM request/response
supabase/functions/kuro-chat/index.ts      Deno: auth, load/save rows, call the model
supabase/functions/kuro-chat/content.ts    GENERATED by `npm run bundle:kuro` (scripts/bundle-kuro-content.ts)
src/net/supabase.ts                        client: lazy supabase-js, anonymous sign-in, sync, invoke
src/net/sync.ts                            pure sync decision table
```

The pure modules import each other with `.ts` extensions (Deno). The client and the tests import
them as ordinary TypeScript (`allowImportingTsExtensions`). `index.ts` alone uses `npm:` and
`Deno`; it is outside the Node typecheck.

## FR1 identity

- 开始 calls `net.signIn()`: `auth.signInAnonymously()` once; the session is kept by supabase-js.
  The names go to `profiles.names` (local `nt_profile` stays the source).
- "绑定邮箱" is not built (no menu string yet; TODO).

## FR2 tables (migration `supabase/migrations/0001_init.sql`)

- `profiles(id uuid pk → auth.users, email text, names jsonb, created_at)`
- `runs(id uuid pk, user_id uuid → auth.users, version int, events jsonb, day int, san int, ended text, conflict_of jsonb, updated_at)`
- `kuro_memory(run_id uuid pk → runs, turns jsonb, summary text, updated_at)`. `turns` is a list of
  `{day, who, text, offline}`.
- `judgement(run_id → runs, day int, truth, values, bond int, evidence jsonb, delta int, pk(run_id, day))`
- RLS on all four:
  - `profiles`: `id = auth.uid()`;
  - `runs`: `user_id = auth.uid()`;
  - `kuro_memory` and `judgement`: through `runs` (`exists (select 1 from runs r where r.id = run_id and r.user_id = auth.uid())`).
- The function uses the caller's JWT (anon key + `Authorization`), so RLS applies to it too; no
  service-role key.

## FR3 the function `kuro-chat`

Input `{ mode: "turn" | "judge", run_id, day, text?, said?, events?: [{id, kind, day, …}] }`.

- **The three sources, in this order** (`buildSystem`):
  1. self: profile + the day's stance / idiom;
  2. the player's background: `kuro-world.md` + the gated slice of the log (`worldSlice(events, day)`: drops `names`, the hand, beat choices and inner lines; adds the desk from day 13 and the dreams on day 15);
  3. memory: summary + recent turns.

  The stable part (1, plus the rubric for judge) carries `cache_control: {type: "ephemeral"}`.
  The login inputs never enter: `names` events are dropped, and the model is told to write
  `{login}` to name the player (the client fills it).
- **turn:** count today's player turns in `kuro_memory.turns` (`decideTurn`). At the limit,
  return the bedtime line, `turnsLeft: 0`, and do not call the model. Otherwise call
  `messages.create({ model, max_tokens: 1024, output_config: { effort: "low" }, system, messages })`.
  - `stop_reason === "refusal"` → 502 (the client falls back).
  - Otherwise append the two turns, upsert memory, and return `{ reply, turnsLeft }`.
- **judge:** the same call with `output_config.format` = the JSON schema (truth / values / bond
  integers −2..2, evidence `[{eventId, note}]`, plus `summary`). Validate it (`validateJudgement`:
  clamp, drop evidence whose id is not in the sent log), upsert the `judgement` row and
  `kuro_memory.summary`, and return it.
- 20 s timeout around the model call (AbortController); any failure is non-200, and the client
  goes offline for that turn.
- **Secrets read:** `ANTHROPIC_API_KEY` (by the SDK), `KURO_MODEL` (optional, default
  `claude-sonnet-5-5`), `SUPABASE_URL`, `SUPABASE_ANON_KEY` (both provided by Supabase).

## FR4 client sync (`src/net/sync.ts`)

`syncDecision(local, cloud)`:

| local | cloud | decision |
|---|---|---|
| any | offline / none | `noop` |
| none | some | `pull` |
| some | none | `push` |
| same version and `updated_at` | | `noop` |
| newer | | `push` |
| older (cloud has a higher version, or the same version and a later `updated_at`) | | `pull` |
| both moved on (cloud newer by version, but local has events the cloud lacks) | | `conflict`: keep local, push it, store cloud in `runs.conflict_of` |

Push on lie-down and every 20 events (the store subscription in main.ts). Pull on boot when
`continue`. All calls are no-ops without `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY`.

## FR5 tests

The sync decision table; `decideTurn` (bedtime at the sixth call); the prompt assembly (order,
cache_control, no names); judgement validation; the function's request/response helpers against a
mocked SDK response; the client fallback with a mocked invoke. Nothing calls the real API.

## 绑定邮箱 (FR1, 2026-11-01)

- Row model (`src/net/email.ts`, pure): `hidden` unless configured and signed in; `bound` when the
  session's user is not anonymous and has an email; otherwise `input` with draft and status
  (idle / sending / sent / error). The draft and status live in the module, so re-renders in the
  game and on the title page keep them.
- Markup (`emailRowHtml` in `world/room/hud.ts`, inside `settingsPanel`, before the actions):
  - a label, an `<input type="email">` (Enter sends) and 发送链接;
  - a status line (`role="status"`) that shows the hint, then sent or error;
  - while sending, the input and button are disabled;
  - bound shows `settings.emailBound`.
- Call (`net.bindEmail(email, origin)`):
  - with a session: `auth.updateUser({ email }, { emailRedirectTo: origin })`, the anonymous →
    email upgrade that keeps the user id;
  - without one: `auth.signInWithOtp({ email, options: { emailRedirectTo: origin,
    shouldCreateUser: true } })`.
  - `origin` is `location.origin`.
  - An address that doesn't look like one, or a server error, shows the error line; typing again
    clears it.
